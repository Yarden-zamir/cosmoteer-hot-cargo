## 49. Run record

A list of the past runs on this machine, with a score, so that each run counts toward something. Code: `src/HotCargo/RunRecord`. Pure logic: `RunRecord/RunRecordModel.cs`.

1220. **File.** The record is a file in the game's save folder (`Paths.SavedGamesFolder`), `hot_cargo_runs.json`. It is not in the repo and not in a career save, so it keeps across careers on this machine. Each machine keeps its own file: in co-op, every player gets the entry of the shared run. A file that does not read (bad JSON, a newer format) is not overwritten. Its error shows where the record shows: the career log block (requirement 1225) and the Past Runs window (requirement 1232).
1221. **Entry.** One entry for each run, by run ID (the galaxy seed, `GameInit.RandSeed`). Limit: two careers with the same galaxy seed share one entry; the later end replaces it. It holds: the end date (local time of the machine), the result (won or lost), the score (requirement 7; 0 for a loss), the delivered units, the game time, the last sector and the run length (requirement 1201), the peak heat, the destroyed vaults (run log lines of requirement 731), the start job (ID and name, section 48) and the human player count.
1222. **When.** While the run on this machine has ended (won or lost), the record holds its entry with the current numbers. The check runs in UI frames and writes only on a change. So the first frame after the end writes the entry, a Buyer delivery after the win updates the score (requirement 7), and a loaded save of a run that ended adds its entry once. No sim state changes. A run that does not end (the player quits) has no entry.
1223. **Peak heat.** The run state saves the highest heat of the run. The sim tick updates it.
1224. **Size.** The file keeps the newest `MaxEntries` (200) entries. Limit: a constant, not a tunable, because it is not a design number.
1225. **Show.** The "Hot Cargo run" tab of the career log (requirement 732) shows "PAST RUNS" above the run log: the best score, and one row for each entry, newest first: the date, WON or LOST, the score, the start job, the sectors, the time, the peak heat and the lost vaults. Without entries it shows "No finished runs yet." A file that does not read adds a line with its error.
1226. **Tests.** Unit tests `RunRecordModelTests`: the upsert by ID, the size limit, the best score, the row order and the file round trip. Autotest `runrecord-entry`: a win writes one entry with the numbers of the run, a later delivery updates it, a load does not add a second one, a loss writes its entry, and the career log tab shows the rows. Screenshot: `docs/screenshots/runrecord-tab.jpg` (`tests/screens/runrecord.txt`).

### Past Runs on the main menu

1227. **Button.** While the mod is on, the main menu top bar has a "Past Runs" button with the Stolen Tech icon, after the vanilla buttons on the left. It opens the Past Runs window. The name matches the "PAST RUNS" block of the career log (requirement 1225), so both places use one term.
1228. **Source.** The window reads the record through the same code as the career log block (`Recorder.Load`, requirement 1220), when it opens. It shows the record of this machine only.
1229. **Table.** One row for each entry, with the columns: date, start job, result (WON or LOST), score, delivered units, time, peak heat, lost vaults and players. The career log block and the table use the same cell texts (`RecordRows.Cell`).
1230. **Sort.** The table opens sorted by score, highest first. A click on a column header sorts by that column: start job A to Z, every other column highest or newest first. A second click on the sorted column turns the order around. The header of the sorted column shows an arrow. Ties go to the newer run.
1231. **Best run.** The won run with the highest score (requirement 1225) has a frame and a BEST mark next to its score, in every sort order.
1232. **Empty and error.** Without entries, the window shows "No finished runs yet." and an empty table. A file that does not read shows its error line and an empty table, and the file stays as it is.
1233. **Tests.** Unit tests `RunSortTests`: the default sort, the header clicks, the text order and ties. Autotest `runrecord-pastruns` (on the main menu, before a career): the button, the empty window, three sample runs sorted by score with the best run marked, the date sort and its reverse, the score reverse, and a file that does not read. Screenshot: `docs/screenshots/runrecord-pastruns.jpg` (`tests/screens/runrecord-pastruns.txt`).
