## 13. Tunables, debug and live tuning

50. The C# code reads all numbers in requirements 1, 4, 7, 12, 17, 19, 23 to 48, 65, 67 to 78, 100 to 104, 130 to 141, 160 to 175, 190 to 202, 221 to 225, 301, 304, 305, 360 to 367, 400 to 412, 561 to 584, 593 to 595, 640 to 660, 680 to 688, 723 and 537 to 541 from `tunables.rules`. `tunables.rules` holds only changed values. The mod writes all values and defaults to `tunables.defaults.rules` at game start.
51. The file uses the game's `.rules` format.
52. The mod watches the file. When the file changes, the mod reloads it within a second, without a game restart: single player applies it at once, and in co-op the host sends it to every machine (requirement 850). The settings menu (requirement 500) writes the same file.
53. If the file has an error, the mod keeps the last valid values and shows the error in game. Errors include values that break sim logic later, for example a stage name that `Hunters.Stages` or a tactic does not match (`TunablesFile.Validate`).
54. Part, resource and mission definitions are mod `.rules` content. A change to them needs a game restart.
55. A heat panel shows heat as a bar with a mark for each stage, the heat rate (time heat with the zone factor, plus the contract trail), the open contracts and the trail rate when any are open, the fleet tech count, the tech value, the stage, the next stage and the sector index. After a win it shows the score. With debug keys on, it also shows the heat value, the heat multiplier and the tunables hash. F8 toggles it. With `Ux.HeatPanel = false`, a text overlay shows the same values. UI switches are in UX.md.
56. When `Debug.DebugKeys = true` (default false), debug keys work: add or remove heat, set the stage, add or remove tech units (F11 / Shift+F11, one unit), and spawn the next stage.
850. Co-op: the host's game watches the host's `tunables.rules`. On a change it validates the file (`TunablesFile.Parse`) and sends it as the `HotCargoTunables` input (requirement 60), so every machine applies it at the same sim tick. A bad file sends nothing: the values in effect stay, and the host's overlay shows the error. A file with the same content as the latest values sends nothing. A client's file has no effect.
851. The open settings window shows a file change within a second, also while the window covers a paused game. A window edit after a file change starts from the file values.
852. New tunables run the `Run.Hooks.TunablesApplied` hook on every machine: in the host's input in co-op, at the reload or the window edit in single player. A higher station fuel floor (`Balance.StationFuelPerMillion`, `Balance.StationFuelMinimum`) tops up the stations of the current system at once, also stations in stasis that remember a stock. A lower floor takes no fuel away.
853. `scripts/tune.sh` changes values in a running run: it writes `tune.request` in the mod folder, one `set PATH VALUE` or `reset PATH` line per change, with the paths of `TunablePath` (for example `Hunters.Stages[2].ShipCount`, `Mechanics.Siege.Seconds`) and the value texts of the settings window. The mod applies all lines as one settings window change (requirements 502 to 504): all or none. It writes `tune.result`: `ok`, the tunables hash and when each value applies, or `error` and the reason. A rejected request changes nothing. In co-op only the host's game takes requests. The skill `.claude/skills/hot-cargo-tune` says how an agent uses it.
854. New tunables replan the hunter groups that wait to arrive (requirement 191): each stage's waiting groups take the ship count and tier of the new stage response and keep their arrival times. A group that the new plan does not have is dropped. The event chances (`Events.ArrivalEventChance`, `StationEventChance`, `CourierChance`) are read at the roll, so a change applies to every roll that did not happen yet.
