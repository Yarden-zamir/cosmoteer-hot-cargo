## 39. One-tile Tech Vault

Code: `src/HotCargo/Tech` (`StartingVault`, `NewGameCheck`, `VaultDesigns`, `StartingResearch`, `Vaults`, `VaultDropPatch`, `DerelictVaultStasisPatch`, `TechMarkers`, `HunterGrab`). Part rules: `mod/tech/tech_vault.rules`. Numbers: the `Tech` tunables section and the part rules.

440. The Tech Vault has one size and no tiers or upgrades. Players decide how many vaults to build, where to put them and how to defend them with hull, armor and shields. Hunters find vaults by the part ID (requirement 34), the vault outline (UX.md H6) marks every vault, and the loss rule counts the tech in all vaults (requirement 9).
441. Vault placement in a design (requirement 1016): vaults go only inside the hull, and only where crew can walk to them. The smallest vanilla storage part (one with a flexible storage grid, nearest to the ship center first) goes like a part that the player grabs: corridor tiles take its place. Its tiles come first; tiles with a door of the storage part come last, so a walkway through the room stays. When none of its tiles gets a vault, the storage part goes back, so the design keeps its storage. Then come corridor tiles (the part that the game leaves on each tile of a grabbed part, `CreatePartPerTileWhenGrabbed`) and empty tiles with a part on all four sides, nearest to the ship center first. A vault goes on a tile only when the game adds its doors like the build tool, crew can walk to it from crew quarters, and every part that had a crew path keeps it. A vault never goes outside the hull. A design with too few such tiles stays as it was, and the report lists it. If crew still cannot walk to a starting vault, a notice at run start asks the player to add a door. On the presets, the 4 vaults fill a 2×2 storage bay (Model-L, Model-C, Model-S), or 4 tiles of a 3×2 bay with a corridor walkway in the middle (Model-M). The autotest `tech-design-vaults` checks the placement on each vanilla starter and that an unused bay goes back. The autotests `tech-start` and `tech-outside` check the vault count, design validity and crew paths to every vault and part. Screenshots: `docs/screenshots/vault-start-model-l.jpg`, `vault-start-model-m.jpg`, `vault-no-tech.jpg` and `vault-crates.jpg` (script `tests/screens/vault.txt`), and `docs/screenshots/starter-<model>-before.jpg` / `-after.jpg` for each preset.
442. A vault holds 2 units, and its storage art shows each unit: 1 unit shows one item, 2 units show two (`StackSprites` `processor_stack_1` and `processor_stack_2`; vanilla picks sprite `(units - 1) / ResourcesPerStackSprite`, `TypedResourceGrid.UpdateSprite`). A crate holds 1 unit (`MaxPerNugget` = 1). A destroyed vault drops or burns only its own units (requirement 445); other vaults keep theirs. The vault health (3,000) and cost (8 steel) are part rules.
443. **Loss timer.** When the fleet tech count reaches 0 and the count is certain (requirement 12), a timer of `LossGraceSeconds` (default 180 s) starts. A toast says so, and the heat panel shows "NO TECH, run lost in m:ss" and a reason in place of the tech line. Tech back before the end (crew pick up crates, an event, a friendly ship returns tech) stops the timer, and the run goes on. At the end the run is lost. The timer advances in the sim tick from sim state only; the run state saves it (`SecondsWithoutTech`, `Tech.LossTimerRunning`, `Tech.LossTimerReason`), and the integrity hash includes its time. API for other areas: `Tech.LossTimer.Start(run, reason)` starts it with a reason, or changes the reason of a running timer; `IsRunning(run)` and `SecondsLeft(run)`. The autotests `tech-timer` and the co-op step `tech.loss-timer` in `coop-combat` check it.
444. **Tech markers.** The vanilla object indicators (zoomed-out map blips and off-screen arrows) show where tech is in the current system: a "TECH n" line on the blip of each human ship with tech in its vaults, and an indicator with the Stolen Tech icon on each tech crate (nugget) in space, on screen and off screen. Other areas register ships that hold tech for the players with `Tech.TechMarkers.RegisterHolders(source)`; their blips get the same line. `TechMarkers` (default on) turns the markers off. GUI only: the markers never change the sim.
445. **Destroyed vaults drop tech.** A destroyed vault drops its tech as crates in space (resource drop rate `StorageDestroyed` = 100 %); deconstruction drops it too. With chance `VaultTechLossChance` (default 0.1) the tech burns instead, and a toast and a chat line say "A vault blew apart: n tech destroyed." The run log has a line for each destroyed vault (requirement 731). The roll uses a random source seeded from the ship, the vault tile and the sim tick, so every client rolls the same. Crates do not count in the fleet tech count; crew bring them back with the vanilla collect order (requirement 447). Crew that die keep losing the tech they carry (requirement 9).
446. **Hunters take crates.** A hunter goes for the nearest tech crate within `HunterGrabRange` (default 3,000) that it wants. It wants each crate with chance `HunterGrabChance` (default 0.8), rolled once for each hunter and crate from their IDs. The AI module `HcGrabTech` sits above the fight tactics and below fall back, call and flee, so a hunter leaves a fight for a crate. A live hunter whose hull comes within `HunterGrabReach` (default 40) of a crate takes it, in the sim tick, hunters in sim order. The tech is gone from the players: it does not count in the fleet. A toast and a chat line name the hunter, and its blip shows "HAS n TECH". A hunter that becomes a wreck spills the tech as crates again (another hunter in reach can take them); a hunter that leaves the system (or of which nothing is left) takes it; a hunter in stasis or in another system keeps it. The run state saves the held tech, and the integrity hash includes its units. The autotest `tech-hunters` checks it.
447. **Rebuild.** An empty vault costs 8 steel, as much as 1×1 armor (4,000 health), so it is easy to rebuild but no cheaper armor. It builds with the career construction mode like any part. Crew move tech into a new vault: crates with the vanilla collect order, tech from other vaults with the move resources tool (requirement 16). The starting ship holds no steel, so the players buy or salvage steel for a new vault. The autotest `tech-drop` checks drop, burn (with a forced roll), a crew-built vault and the pickup of crates into it.
448. Removed: vault heat resistance (`VaultSunHeatFactor`). It kept sun dives from costing tech through partial damage, and partial damage no longer costs tech (requirement 65). Heat damages a vault like any part.
449. **One tech count.** The fleet tech count reads the vault storage (the units that the vault art shows) of every human ship and every derelict ship in the system, plus tech that crew carry for the players (`Vaults.CountFleetTech`). Vaults exist only on player ships, so a vault on a derelict holds the players' tech. A derelict is a ship with the junk owner (`Ship.IsJunk`): a human ship that lost its control rooms or a piece that broke off one. Its tech can still come back: players can salvage a derelict (`SimModeManager.CanSalvage`), and a salvaged vault drops its tech as crates (requirement 445). So it counts, and the loss timer does not start while it is there. Vanilla puts a junk ship that no player sees into stasis, where it leaves the sim (`CareerSimModeManager.GetShipStasisMode`, `SimStasisManager.UpdateStasis`). A derelict that holds tech is exempt from stasis, so it stays in the sim, in the count and on the map. Held tech (requirement 575) counts too. Crates in space do not count (requirement 445). The heat panel, the loss rule, the heat multiplier and telemetry use this one count. Under the total, the heat panel says where the tech is: in co-op the local player's share when others hold some ("you hold 2"), the units in derelict ships ("2 in a derelict ship"), and, outside the total, crates in space ("+2 in crates") and tech that hunters hold ("hunters hold 1"). A derelict's blip shows "TECH n" like a human ship (requirement 444). The autotest `tech-count` and the co-op step `tech.coop-count` in `coop-combat` check it.

### Starter ships with vaults

1010. **Vaults are required.** A Hot Cargo career starts only with a ship whose Tech Vaults hold all `StartingTechUnits`. The vanilla career ship check (`CareerModeRules.IsShipDesignLegal`) refuses other ships, in the new-game screens and when the game creates the player ships (`CareerGameModeManager.FinishInitNewGame`), like `PvpModeRules.RequiredPartCategories` in PvP. The check applies only while the mod is enabled.
1011. Single player reads `StartingTechUnits` from the local `tunables.rules`. Co-op uses the default, because a co-op run starts with the default tunables (`Run.Start`). In co-op every ship needs vaults for all units, though it gets only a share (requirement 17). Limit: a co-op host that changes `StartingTechUnits` does not change the check; revisit when co-op starts with the host tunables.
1012. A refused ship shows the vanilla "invalid ship" dialog with the Hot Cargo reason: the tech to hold, the vaults that need, and the tech that the ship's vaults hold.
1013. The autotest `journey-newgame-check` checks that every preset passes, that a vanilla starter fails, and the dialog text.
1014. **Fill only.** At the start of a new run the code only fills the vaults that the starting ships have. It builds no vault. A career save from before the mod can have ships without vaults: the units that find no room are lost, and a notice says so.
1015. **Starting research.** A new run unlocks the career techs in `StartingResearch` (default `cosmoteer.hyperdrive_small`, the small FTL drive). An unknown tech ID stops the run start with an error. The autotests `tech-start` and `journey-newgame-check` check it.
1016. **Design tool.** The autotest command `vaultdesigns <source>|<output>` builds vaults into each `*.ship.png` of a folder with the game's own code: it loads the design into the running game, places vaults for `StartingTechUnits` (requirement 441), checks the design (valid blueprints, the new-game check), and saves it with the game's Save Ship code. Before the save the design runs for a few seconds in the game with full power and supplies and its crew (`InitializeToMax`, like a new career ship). The crew walk to their posts, so the picture shows the manned parts lit. The design file keeps no crew. A design that already has a vault is skipped. A design that fails keeps its source version: with another output folder, the tool copies the source file there. Saving needs graphics, so the tool runs in the player's game slot. It writes `vault-report.txt` in the mod folder.
1017. **Presets.** `mod/tech/starters/*.ship.png` are the vanilla starters with vaults, built by `scripts/vault-saved-ships.sh --starters mod/tech/starters` from `Data/builtin_ships/Starter`. Rules actions replace the ship files of the career `StarterShips`.
1018. **Saved ships.** `scripts/vault-saved-ships.sh` adds vaults to the player's saved ships (the `Saved Ships` folder of the save folder, `Paths.SavedShipsFolder`). It runs only when the player's game is closed, under the main-slot lock. It first copies the whole folder to `Saved Ships.backup-<date>-<time>` next to it and checks the file count. With `--from <folder>`, the designs come from that folder of the save folder (an earlier backup), which the script only reads. Then it prints the report and installs `origin/main` back into the player's game.
