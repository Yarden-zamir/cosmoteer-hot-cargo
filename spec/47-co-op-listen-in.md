## 47. Co-op listen-in

In co-op, the other players listen in on a running hail and vote on its choices. Code: `src/HotCargo/SharedChoice/ListenIn.cs`, pure rules in `ListenInModel.cs`, the read-only rules in `src/HotCargo/Ui/CommsHail.cs`. Votes use section 32.

1131. **Hails.** A hail runs while a player's ship has open comms with a ship that shows a dialogue tab to it. The source is the vanilla sim set `CareerSimModeManager.OpenComms` (changed by `MPOpenCommsInput` and `MPCloseCommsInput`), so every machine has the same hails and listen-in sends no new message.
1132. **Listen list.** Every other player sees a "Listen in: <player> talks to <ship>" button above their own comms button (above the comms box while it is open, above the tool row while no ship is selected). With several hails the list has one button per speaker and ship, ordered by ship ID. The list refreshes every `Ux.HudRefreshSeconds` (requirement 872). Decision: plain "talks to" instead of an arrow, because the game font may lack the arrow glyph.
1133. **Listen window.** A click opens the vanilla comms window with the speaker's ship as caller, in listen mode, and a second click closes it. It shows only the dialogue tab: the same live page as the speaker (text, rows, choices, the shared draft, hovers and votes). Listen mode sends no open comms, close comms or pause input.
1134. **Read-only.** A listener cannot make the choice: vanilla dialogue buttons, Hot Cargo hail lines and multiselect rows are off. Shared choice buttons and action rows stay on, and a click on one is a vote. Digit keys follow the same rules.
1135. **Vote mode.** In vote mode a listener's vote is a normal vote (requirements 604 to 606). A vote is not a pick, so in vote mode a choice that closes the window on a pick (for example "Fight") keeps it open for the speaker too, and the voter sees the votes.
1136. **First pick mode.** In first pick mode a listener's vote is advisory: the `HotCargoSharedChoice` input records it, every page shows it, and the sim tick never decides it. The speaker (any player in the channel) picks. The bar of a listener says that the speaker picks. "Decide now" stays a vote mode action.
1137. **Follow.** The listen window rebuilds its page each frame from sim state, so a pick shows its result as for the speaker. A pick that the sim takes clears the advisory votes of that page. When the speaker's channel closes, the title says so, and the window closes `ListenLingerSeconds` (4) real seconds later. It also closes when the dialogue tab goes away.
1138. **Determinism.** The listen list and listen windows are UI state. A listener who opens or closes a window changes no sim state. Single player shows no list.
1139. **Limits.** Players that share ships share a player index, so they cannot listen to each other. Vanilla dialogue buttons (vanilla surrender, bounty) and hail lines show but take no votes, because they are not shared choices.
1140. **Tests.** Co-op steps `sharedchoice.listen-event` (`tests/autotest-mp/coop-economy.txt`: a ship that carries an event page, first pick mode) and `sharedchoice.listen-hunter` (`coop-combat.txt`: a hunter's demand page, vote mode). Unit tests: `ListenInModelTests`.
