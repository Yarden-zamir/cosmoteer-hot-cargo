## 44. Invariants and the playthrough test

Code: `src/HotCargo/Dev/Invariants.cs` (rules), `src/HotCargo/Dev/Playthrough.cs` (playthrough commands). Test: `tests/autotest/core-playthrough.txt`. Numbers: the `Invariants` tunables section.

990. **Invariants.** A checker tests rules that must always hold while a run is active. A broken rule writes one line `ERROR invariant <name>: <details>` to `hot_cargo_log.txt`, once for each rule and subject in a game session. Every autotest fails on an ERROR line, so each test checks every rule. Telemetry records every log line (`log` event), so playtests show broken rules too. The checker only reads the game: it never changes sim state, so co-op stays in sync, and it does not show in the overlay.
991. **Tech in vaults** (`tech_count`). On each human ship, the stored tech that the fleet count reads (`GetResourceTotal`) equals the units in its Tech Vault grids, the units that the vault art shows (requirements 14 and 59).
992. **Vault hits** (`vault_hit`). A health change of a vault that does not destroy it costs no tech (requirement 65): the units in the vault stay the same. The check runs after every other patch of `Part.OnHealthChanged`.
993. **Heat range** (`heat_range`, `heat_stages`). Heat stays in 0 to 100 (requirement 29), and the started stages are exactly the stages that the heat reached.
994. **Chain ships wait** (`hostile_chain_trigger`). A ship with an `hc_ch_` tag and the hunter AI (`HotCargoHunter`) does not attack the players while no chain mission is in progress: a stage mission that the players accepted, or a Return or Arrival mission, which goes straight to the log. A ship of a stage offer, with any AI, does not attack before the accept (requirement 1127). After its stage ends, a guard with the vanilla `Normal` AI may defend its post like a vanilla bounty guard.
995. **Hunters wait** (`hostile_hunter_trigger`). A hunter (`hc_hunter`) does not attack the players while heat is 0 or no stage started, unless a hunter wave spawned in this game session (a stage, a strike wave, an informant, an event or a test command). Limit for 994 and 995: "attacks" means an attack command on a human ship; a weapon that fires at a ship in range without a command does not count.
996. **Markers end with their mission** (`mission_marker`). A mission marker is a target area marker (`cosmoteer.poi_target_area`) that an objective owns (`Missions/MissionMarkers.Of`): the POI of a vanilla objective (`POIDoodadID`) or the marker of a Hot Cargo objective (`IMissionMarkers`). A map ring that a mission only uses (a belt pass for Hold the Pass) is not a mission marker. When a mission leaves the log (completed, failed or abandoned) or an offer is dismissed (requirement 103), its markers go, unless another mission in progress or offer owns them. Vanilla removes a bounty marker only when its ships die, so an abandoned bounty kept its marker before. The rule: a marker that a mission owned at an earlier check and that no mission in progress or offer owns in two checks in a row breaks it. Limits: the cleanup works in the current system only, and a marker whose mission ends before its first check is not seen.
997. **Rivals are symmetric** (`rival_symmetric`). When accepting offer A dismisses offer B, accepting B dismisses A, and no offer names itself or a copy of itself (requirement 103). One offer can sit in several offer lists as copies with the same `MissionID`, so the check compares offers by `MissionID` (`ContractBook.RivalsOf`).
998. **Shown text** (`shown_text`). Text that the game shows has no raw markup: no tag in a renderer without XML formatting, no escaped tag (`&lt;`) in a renderer with XML formatting, and no unfilled `{placeholder}`. The check runs at the end of the frame for each text renderer whose text or XML switch changed in that frame. It reads widgets only.
999. **Heat sources** (`heat_source`). Every heat change comes from a documented source (TELEMETRY.md, "Sources and causes"): a change whose caller matches no source rule breaks the rule. Limit: it runs only while the Telemetry `Heat` category is on.
1000. **Switch and cost.** `Invariants.Enabled` (default on, in tests and in play) turns every rule off. The rules that read the whole system run every `Invariants.CheckSeconds` (default 1) game seconds; the vault, heat source and text rules run at their event. Telemetry measures the cost with the rest of the mod.
1001. A rule that a correct game breaks is a wrong rule: fix the rule in place, and fix its line here. A rule that a real bug breaks stays, and the bug gets fixed.
1002. **New hunters are hostile** (`hunter_spawn_hostile`). A hunter that the mod spawns (`HunterSpawner.SpawnWave`) has no human player index and is an enemy of every human ship (requirement 33). Playtest 2026-11-13: new hunters copied the index of a hunter ship that the players owned, and joined their fleet. The check runs at each spawn. The players can take a hunter ship over later; that does not break the rule.
1003. **Hunters are one side** (`hunter_one_side`). The hunters of a system, live and in stasis, have one player index (requirement 33). Wrecks and hunter ships that the players took over do not count.
1004. **Playthrough test.** `core-playthrough` plays a new single-player run the way a person does, with no godmode, no teleports, no test damage and no free money or tech: ship AI tactics on with a preset, fly to the nearest station, accept the local fight with the lowest threat (the lowest tier, then the fewest targets with the Disable tactic, because the starting ship carries no steel to rebuild shot thrusters and control parts, then the nearest), right click its target ship again every 20 seconds as it moves (the ship AI fights) until the fight steps end, fly back (slowly, when the thrusters are shot), collect the reward (a vanilla bounty ends with a ReceiveRewards step, `sysgen_bounties.rules`: call the station, receive payment), sell 1 tech, repair with the build window's repair button and buy what it costs, unlock and build a small hyperdrive, buy steel, coil and hyperium, fly to the relay toward an unvisited system with the fewest enemy ships near the straight route (live or in stasis), then the nearest, order the relay jump and press ENGAGE. It passes when the run reaches sector 2 with tech above 0 and no invariant broke.
1005. Each playthrough command (`pt_*`) sends the input of one player click: a right click order (`MPEnqueueCommandsInput`), a comms button (`MPAcceptMissionInput`, `MPMissionPaymentInput`, `MPBuyTechInput`), a trade window transfer (`MPMoveResourcesInput`), or a build window button (`MPUpdateShipInput`: build confirmation, repair all). The headless slot draws no frames, so after the jump the test unpauses the sim (journey-jump.txt).
1006. The playthrough runs in the full suite only. Its script asks for a longer timeout with a `# timeout: <seconds>` line, which `scripts/autotest.sh` reads.
1007. **Test clock.** While a run is active and its sim ticks, script waits (`wait`, `waitfor` timeouts) and the repeated orders of the `pt_*` commands count the run's game seconds, so a test means the same on a loaded machine; at other times they count real seconds. A timeout ends only after both its game and its real seconds. Each wait has a real-time budget, so a hung game still fails. `waitreal` and `waitforreal` count real seconds only, for files, the network or another process. Measured 2026-11-14 with 8 co-op sessions at once on one Mac: the hosts ran at 23 to 77 % of real time, so a real-time `wait` covered that much less of the game than the script says.
