# Hot Cargo UX pass

UI and UX findings for vanilla Cosmoteer 0.30.5a and the Hot Cargo mod, the changes, and their status.
Each change has an on/off switch in `Ux` in `tunables.rules` (class `src/HotCargo/Ux/UxTunables.cs`). All switches default to on.
A switch change takes effect within a second (live reload: single player, and the host's file in co-op).

All changes are GUI-only, with one exception: the comms pause (V17) pauses through the game's own pause input, which is deterministic. So co-op multiplayer stays in lockstep.
A failing UI patch logs one error, shows it in the overlay, and leaves the vanilla UI in place (`UxKit.Guard`, which calls `Core/Errors.cs`).

## How to read the table

- **Impact**: how much a player gains (high, medium, low).
- **Cost**: implementation size and risk (S, M, L).
- **Status**: **done** (in this branch), **later** (not done, with the reason).

### Watched supplies (V7)

The supplies that V7 watches come from the part rules, not from a list: every resource that a `ResourceConsumer` component consumes, on a part that has no `provides_*` type category, toggled component sets included. Factories have a `provides_*` category, so their inputs are out.

In 0.30.5a this gives: battery, bullet, hyperium (FTL drives), mine_part, missile_part_he, missile_part_emp, missile_part_nuke, missile_part_thermal. Carbon is out (only the diamond factory consumes it). Hot Cargo's stolen tech is removed by name: the Tech Vault consumes it, but it is cargo with its own UI. The log line `ux: watched supplies: ...` shows the set at game start.

Fractions use typed capacity only, because cargo holds count as capacity for any resource.

## Screenshots

`scripts/screens.sh tests/screens/<name>.txt <out-dir>` takes the screenshots of one script in the player's game (slot main) and copies the PNGs to `<out-dir>`.
It waits for the lock `/tmp/hot_cargo_main_slot.lock`, stops a running main-slot game, deploys this worktree, runs the script minimized and quits the game.
Look at each image before you commit it. Crop anything that shows a user name, a file path or a Steam name.
`docs/screenshots/polish/` holds before and after pairs of the visual pass (`<name>-before.jpg`, `<name>-after.jpg`).

### How the capture works (no focus, no visible window)

1. The scripts start the main-slot game minimized. Headless test slots have no graphics device (`NullGraphicsManager` throws on a screenshot), so screenshots need the main slot.
2. The D3D11 graphics manager skips all drawing while the window is minimized: `CanRender => !Window.IsMinimized` (HalflingPlatformWDX), read by `Director.DoDraw`.
3. The autotest command `render on` patches that getter to return true (`Ux/Screenshot.cs`). The game then draws each frame into the swap chain back buffer, which keeps the last window size. `Present` still skips, because DXGI reports the minimized window as occluded. Nothing shows on the screen, and the window never gets focus.
4. `screenshot NAME` waits for the end of a frame, copies the back buffer (`GraphicsManager.GetEndOfFrameScreenShot`) and saves `Mods/hot_cargo/screenshots/NAME.png`. It hides the hover tooltips for that frame, because the real cursor rests somewhere over the hidden window. It never moves the real cursor.
5. Hover tooltips do not show in a capture, so `tipshow map|mapcur|station|fame|text <xml>` shows one at a fixed spot, and `tipclear` removes it.
